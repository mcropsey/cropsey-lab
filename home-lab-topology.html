Lab agents

Scheduled on .98 · every LLM call goes through LiteLLM on .101 with the agent's own key · one local model, one request at a time

LLM requests (OpenAI-compatible, per-agent key) Inventory feeds cvewatch + patchwatch Reports + email

How the agents work

Code in ~/mikes-agents on .98 · github.com/mcropsey/mikes-agents

1Schedulesystemd timers on .98 start each agent before the workday (05:30–06:45). Every agent can also be run by hand: secnews, labwatch, cvewatch, patchwatch.
2GatherReal data only: security feeds and CISA KEV, Prometheus/Loki/Alertmanager, the NVD API, the SSH inventory of every host, container registries.
3Reason + toolsThe model ranks and explains. labwatch runs a real tool loop: it writes its own PromQL and LogQL to confirm problems before reporting.
4Through LiteLLMEach agent uses its own key, linked to its LiteLLM agent entry, locked to qwen3.8-27b with 1 request in flight.
5ReportHTML + JSON saved on .98 and emailed. cvewatch only emails when the lab is affected. Nothing is changed on any host.

secnews 06:00

BleepingComputer, The Hacker News, Krebs, SecurityWeek, Dark Reading, The Record, SANS ISC, CISA advisories, Schneier + new KEV entries. Dedupes and ranks 8–15 stories with severity, CVEs and an action.

key secnews-agent1 call · ~1.5 min

labwatch 06:15

14 PromQL checks, Loki error counts and Alertmanager, then up to 8 rounds of its own queries. GREEN / YELLOW / RED briefing with per-issue actions.

key labwatch-agent~10 tool calls · ~1.5 min

cvewatch 06:30

New NVD CVEs + KEV matched to installed packages, container and k8s images, grouped per product. Verdict per group: affected / possibly / not affected, with the Rocky fix if one exists.

key cvewatch-agent1 call · email only on a hit

patchwatch Mon 06:45

Pending updates, Rocky security advisories with CVEs, reboot-needed hosts, broken repos, and images whose registry tag has a newer build. Prioritised plan with commands. Reports only.

key patchwatch-agent1 call · ~3.5 min

labinventory 05:30

No LLM. SSH + sudo -n from .98 to the 11 managed hosts (not .77/.78): packages, updates, advisories, containers with digests, k3s/microk8s pod images.

runs as mcropsey~25 s
One model onlyEvery agent key allows only qwen3.8-27b, so LM Studio never loads a second model next to it.
One request at a timemax_parallel_requests: 1 and 30 rpm per key. LiteLLM queues calls instead of stacking them on the GPU.
Before the workdayAll schedules finish before 07:00: about 5 GPU-minutes a morning, plus ~3.5 on Mondays.
Guardrail opt-out, per keybasic-safety-filter stays on for everything else; only the 4 agent keys opt out (security vocabulary trips it).
Read-onlyThe agents never change hosts. Patching and reboots are separate, done on request (2026-10-07).
No secrets in gitKeys and the Gmail app password live only in root-only env files on .98.

How the registry fits in

Each agent has an entry in LiteLLM's agent registry (/v1/agents) with an agent card: description, host, schedule and skills. Its virtual key carries the matching agent_id, so every request is attributed to the agent on the Agents page.

No A2A URL: these are scheduled clients, not A2A servers. The 7 Agent Lab personas were removed when the Agent Lab was retired (~2026-10-05).
