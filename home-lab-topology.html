AI agent traffic

Every agent call goes through LiteLLM on .101 with its own virtual key; one model, one request at a time

LLM requests (OpenAI-compatible, per-persona key, tagged persona/host) Structured run logs

How the agents work

Code in ~/agent-lab on .101 · deployed with ./deploy.sh

1ScheduleAPScheduler wakes each persona after a jittered wait: rate × intensity × time of day. 08:00–22:00 is a trickle (~1.4 runs/h lab-wide); nights run ~10.5/h.
2GenerateThe persona builds its job: a Faker ticket, fake service logs, a SQL question, live RSS items, a customer persona or a code diff.
3Reason + toolsIts framework (PydanticAI, LangGraph or OpenAI Agents SDK) calls the model and runs tools: lookups, file search, SQL, CRM actions.
4Through LiteLLMEach call uses the persona's virtual key, linked to its registered LiteLLM agent; a shared layer tags it and meters tokens, tools, latency and cost. ~2% of calls are sent wrong on purpose.
5LogOne JSON line per run: persona, host, model, tokens, latency, tool calls, success, errors, cost. Shipped to Loki for the dashboard.

Ticket triage PydanticAI

Faker support tickets (half written by the LLM, some with fake PII). Looks up the customer and status page, then returns category, priority, PII flags and a draft reply.

host .100key agent-triage~2 calls

SRE log analyst LangGraph

Writes 300–1500 lines of service logs with one incident (DB pool, OOM, expired cert, disk full, latency, login failures), investigates with list/read/search tools and writes an incident summary.

host .100key agent-sre~7 calls · 40–60k tok

Data analyst LangGraph

Random business questions over the Chinook SQLite DB with a read-only SQL tool. Errors go back to the model so it retries; 20% of runs get a stale schema hint.

host .85key agent-analyst~5 calls

News digest PydanticAI

Pulls 2–3 public RSS feeds (BBC, Ars, HN, The Register, NASA), summarizes each item, tags topics and writes an overview. Canned articles when offline.

host .85key agent-news1 call · big output

Customer ↔ support Agents SDK

Two agents, two keys: a customer with a random temperament and goal chats 3–8 turns with a support agent that uses fake CRM tools (refund, address change, reset, escalate).

host rk1keys agent-customer · agent-support~17 calls

Code reviewer Agents SDK

Reviews bundled diffs with planted bugs (SQL built from strings, data race, missing await, hardcoded secret, public bucket) or synthetic diffs of the lab's own code, with up to ~15k tokens of context.

host rk2key agent-reviewerlong context
One model onlyKeys are locked to agentlab-main (qwen3.8-27b). Asking for another model gets a 403, so LM Studio never swaps models.
One request at a timemax_parallel_requests: 1 on the route: LiteLLM queues agent calls instead of stacking them on the GPU.
Daytime back-offA slow daytime call (>20 s at <20 tok/s) means the GPU is busy with real work: that host pauses 30 min.
Errors that never hit the GPUBad model names (403), over-long prompts (pre-call check, 400) and rate-limit bursts (429) are all refused by LiteLLM.
Budgets + limitsPer key: rpm 20–30, tpm 120–250k, $1/day on simulated pricing. Team agent-lab groups the 9 keys.
Kill switchglobal.enabled: false in config/lab.yaml + ./deploy.sh config, or ./stop.sh to stop every host.

How the registry fits in

Each persona has an entry in LiteLLM's agent registry (/v1/agents) with an agent card: description, framework, host and skills. Its virtual key carries the matching agent_id, so every request is attributed to the agent and the Agents page shows spend and activity per agent.

No A2A URL is set: these agents are scheduled clients, not A2A servers, so they can't be invoked from the UI. Chaos bursts and the unused red-team key aren't registered. Spend is attributed from 2026-09-29 21:25 CDT on.
